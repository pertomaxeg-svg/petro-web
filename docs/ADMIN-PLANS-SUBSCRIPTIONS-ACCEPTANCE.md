# إدارة الخطط والاشتراكات — قبول التنفيذ

التاريخ: 15 أكتوبر 2026. النطاق حصريًا `Pertomax EG`، قاعدة Supabase المرجع `msvgzsfzrqlrfpstthhe`، ومستودع `pertomaxeg-svg/petro-web`.

## ما أُنجز في نسخة التطوير

- أُضيفت عقود OpenAPI وعميل API ومسارات مالك المنصة لكتالوج الخطط، وإصداراتها، وجدولة إيقاف استقبال الجديد، وطلبات الاشتراك ومراجعتها وإلغاء الاشتراك بتاريخ مستقبلي.
- أُضيفت واجهتا الخطط والاشتراكات داخل إطار الإدارة المركزية نفسه، مع بحث وفلاتر وترتيب وصفحات محلية، تفاصيل الإصدارات والنسخ، نماذج عربية RTL وحالات تحميل/خطأ/صلاحية/مخطط غير مفعّل. تُختار الجهات والفروع من السجلات الفعلية؛ لا توجد بيانات عرض اصطناعية.
- تعرض الواجهة مرجع الأسعار المعتمد: الشركات 500/750/1000 ج.م لكل مركبة سنويًا، ومقدمو الخدمات 5000 ج.م لكل فرع سنويًا، والمحطات مجانية بلا عمولة أو رسوم غسيل. رسوم إصدار NFC هي 100 ج.م منفصلة عن الاشتراك. لم تُضف ضريبة أو تركيبًا أو استبدالًا أو خصم ترقية نسبيًا.
- الإصدار الجديد يبدأ بحقوق وإعدادات فارغة غير معتمدة؛ لا يمكن نشره حتى اعتماد كل بند. تبقى الحقوق القديمة غير الموثقة ظاهرة بهذه الصفة، ولا تُعامل كميزات منشورة.
- يحفظ نموذج الطلب الجهة/الفرع ونوع الطلب ونسخة الخطة والسعر المطلوب والنطاق والسبب والتواريخ. التغيير على الاشتراك السابق غير متاح؛ تتغير حالته فقط بإلغاء مستقبلي مسبب، مع بقاء لقطات السعر والحقوق وتواريخها.
- للمحطة المجانية مسار فرعي مستقل. يرفض مسار الشركة التفعيل/الإرسال المدفوع عند غياب سجل أسطول موثوق. انتهاء فرع مقدم خدمات لا يحجب فروع الجهة الأخرى في دالة التحقق الخاصة بالنطاق.

## حدود التفعيل المعتمدة

- ترحيل `0010_plan_subscription_admin.sql` جديد على قاعدة اختبار مؤقتة فقط. نجحت اختبارات PostgreSQL المعزولة للنسخ والأسعار والنطاق ومنع التكرار والتداخل والعزل بين الجهات والحقوق/اللقطات غير القابلة للتعديل والحالة المدفوعة المنتظرة والمحطة المجانية ورفض السعر المخصص للمحطات ومنع غياب سجل أسطول الشركات وتغيير الخطة والتجديد والإلغاء المستقبلي وانتهاء فرع دون بقية الفروع.
- لم يُطبق 0010 أو أي ترحيل جديد على Supabase الحية، ولم تُنشأ أو تُراجع أو تُلغَ اشتراكات حقيقية، ولم تُنشأ دفعة أو محفظة أو بيانات أسطول وهمية. لم تتغير بيانات الجهات القائمة.
- يُرجع API حالة انتظار للمخطط المفقود؛ الأزرار الرئيسية معطلة عند خطأ 503. لذلك لا يُدّعى أن إدارة الاشتراكات مفعلة حيًا.
- لم توجد في البنية المفحوصة نواة مالية موثوقة لقبض رسوم الاشتراك، ولا سجل أسطول مركبات معتمد. لا يُعتبر إثبات مرفق قبضًا. أي طلب مدفوع معتمد يبقى `pending_payment` حتى ربطه بالمالية، ولا ينشئ رصيدًا.
- دالة السماح بخدمات جديدة حسب اشتراك الفرع موجودة داخل المخطط الخاص في 0010، لكنها غير موصولة بنقاط إنشاء الخدمات الحالية؛ لا توجد ضمن هذه الحزمة خدمة قائمة نُعدّلها لفرض هذا الشرط، ولا يُفترض مستهلك خارجي. يلزم ربطها واختبارها عند بناء/مراجعة خدمات المستهلك.
- قيمة تغطية الشركات غير قابلة للإثبات دون سجل مركبات؛ لم يُنشأ أسطول أو مركبات وهمية. يظل ربط وحدة المركبة بخدمة أسطول معتمدة عملًا لاحقًا.

## تحقق البرمجيات والواجهة

- `bash lib/db/rebuild/run-local-test.sh`: نجح على PostgreSQL مؤقت، وشمل 0004–0010 في البيئة المعزولة فقط؛ لا اتصال حي ولا Secrets.
- `pnpm --filter @workspace/pertomax-eg-web run typecheck`: نجح بعد إضافة الواجهات.
- اختبارات API السابقة لـ0008/0009 المعزولة ناجحة، واختبار التكامل المحلي لخدمات SQL الجديدة ناجح. لم تُنشأ جلسة مالك حقيقية ولم يُتجاوز تسجيل الدخول؛ صفحات الإدارة المحمية لا يمكن التحقق بصريًا داخل متصفح المعاينة غير المسجل.
- استُلهم تنظيم المساحات والجداول والفلاتر وهرمية الحالة من المبادئ التي حددها المالك، مع الحفاظ على هوية Pertomax وإطار الإدارة الحالي. صفحات المراجع الرسمية لم تكن متاحة للاسترجاع في المحاولة (استجابات تقييد/رفض)، لذا لا ندّعي مراجعتها أو نسخ تطبيقها.
- جرى فحص توافر `ui-ux-pro-max` و`web-design-guidelines` و`vercel-react-best-practices` في البيئة؛ لم تكن مثبتة، ولم تُثبت أي مهارة أو مكتبة من مصدر خارجي. استُخدمت مراجعة تصميم مخصصة لتوجيه الواجهة ثم طُوبقت عقودها على API الفعلية للمشروع.

## القبول المتبقي

1. حل اختلاف ACL بين القاعدة الحية وإعادة بناء ما بعد 0007 ومراجعة خطة الرجوع؛ ثم إعادة preflight وموافقة المالك قبل أي ترحيل حي. التفاصيل في `docs/PLATFORM-USER-ADMIN-ROLLOUT.md`.
2. بناء/اعتماد ربط مالي موثوق للقبض قبل أي تفعيل مدفوع أو إثبات إيراد.
3. اعتماد سجل أسطول وحقوق/إعدادات كل خطة، وربط بوابة انتهاء الاشتراك بخدمات الإنشاء التي تعتمد على الاشتراك.
4. اختبار جلسة مالك مصرح بها في المعاينة بعد تهيئة المخطط، دون إنشاء حسابات أو اشتراكات حية لأغراض الاختبار.

لا يُطبّق 0009 ضمن الحزمة، ولا تُسحب صلاحية `petro_set_account_status(uuid,text)` القديمة.
