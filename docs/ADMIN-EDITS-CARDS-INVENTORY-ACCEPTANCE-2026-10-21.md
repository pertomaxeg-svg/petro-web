# Pertomax EG — قبول تحديث تحرير الإدارة والبطاقات والمخزون

التاريخ: 2026-10-21
النطاق: إدارة الباقات والكتالوج، مدخل البطاقات، نموذج المركبة، وتنقل مستندات المخزون. لا يبدأ هذا التحديث حزمة جديدة.

## مصفوفة القبول

| البند | التنفيذ | الدليل والنتيجة | الحد المتبقي |
|---|---|---|---|
| تعديل الباقات | ملاحظة التدقيق اختيارية عند إنشاء الخطة والنسخة وتعديل المسودة والأسعار الافتراضية. يسجل API وصفًا إداريًا محايدًا عند تركها فارغة، مع حفظ الممثل والوقت والتغيير. | اختبار HTTP/PostgreSQL محلي أنشأ مسودة وعدّل إعدادات دون إدخال ملاحظة. واختبار رفض النشر دون سبب صريح. | لا تعديل على القاعدة الحية؛ لا تزال نسخة الشروط المنشورة غير قابلة للتعديل بأثر رجعي. |
| ملاحظات الكتالوج | الإنشاء والتعديل ومسودات الأسعار لا تتطلب نصًا يدويًا؛ يسجل API وصفًا إداريًا عند تركه فارغًا. أسباب تغيير الحالة والنشر والإلغاء والمراجعة وإزالة الصورة مطلوبة صراحة. | اختبار HTTP محلي أنشأ صنفًا دون ملاحظة، ورفض تفعيل صنف دون سبب. | لا أسعار وقود حية ولا بيانات تجار اختبارية في Supabase. |
| مرجع الوقود | تحقق اختبار API من اسم التصنيف العربي «الغسيل»، واسم الوحدة «لتر»، ودقة الوحدة، وقراءة أنواع الوقود بوحدة متوافقة وعدم وجود سعر حي افتراضي. | اختبارات API/SQL المعزولة نجحت؛ بناء الواجهة أنتج جدول الوقود وحاسبة السعر في تخطيط كامل العرض. | لا توجد معاينة مخولة مسجلة الدخول عبر أداة الاختبار؛ لا يدعي هذا التوثيق اختبار واجهة المالك الحية. |
| إدارة البطاقات | مدخل مستقل `/admin/cards` في القائمة المركزية؛ مسار `/admin/fleet/credentials` القديم يوجّه إليه. | فحص الأنواع وبناء الويب نجحا بعد تعديل المسارات. | تنقل المالك داخل الجلسة الحية لم يُتحقق منه بأداة المتصفح. |
| نموذج المركبة وPIN | صيغة اللوحة المعيارية توضيحية ومشتقة من الأصل، ويوفر النموذج توليد PIN من أربعة أرقام باستخدام مولد عشوائي آمن، وإظهارًا مؤقتًا قبل الإرسال، ثم يمسح الرمز بعد نجاح الربط. | فحص الأنواع وبناء الويب، إلى جانب اختبارات الأسطول المعزولة القائمة. | لا يمكن استرجاع PIN قديم من بصمته؛ لا توجد آلية إظهار مستمر. اختبار الرفع والتنزيل من Supabase Storage الحي غير منفذ. |
| التحويل والجرد | بعد إرسال مستند تحويل أو جرد من نموذج الأرصدة يعود العرض إلى تبويب التحويلات أو الجرد المقصود. | فحص الأنواع وبناء الويب؛ اختبارات API/SQL للمخزون تشمل 90 تحققًا مركّزًا على الصلاحيات والعزل والذرية والتكرار والتزامن. | لم تُنشأ مستندات أعمال حية ولم تُختبر الواجهة الداخلية بجلسة مالك عبر أداة المتصفح. |
| سلامة الحسابات والصلاحيات | لا إنشاء بيانات أو معاملات حية. الأسباب الصريحة بقيت مطلوبة للإجراءات الحساسة؛ لا إضافة صلاحيات أو ACL. | فحوص الأنواع الكاملة وبناء API والويب، واختبارات SQL وHTTP المعزولة. شملت النتائج المنشورة 52 تحققًا للأسطول والتمويل، و47 لقراءات ملفات الجهات، و90 للمخزون، و36 لمسارات الأسطول؛ وأُعيد تشغيل مجموعة التكامل الكاملة بنجاح. | الأعداد تخص مجموعات منفصلة، وليست مجموعًا موحدًا ولا اختبارًا بصريًا حيًا. |

## أثر Supabase والترحيلات

- لم يُنفّذ أي ترحيل جديد، ولم تُكتب بيانات أعمال أو أسعار أو حسابات اختبارية إلى Supabase.
- تستخدم مسارات API الحالية سببًا إداريًا افتراضيًا محايدًا عند ترك ملاحظة التعديل العادي فارغة؛ لذلك لا يلزم تغيير قيد القاعدة الحية.
- بقي `0009` مؤجلًا، ولم تُعَد أي ترحيلات أو baseline. حالة `0021` السابقة لم تتغير.

## حدود المعاينة

فحص الأنواع وبناء التطبيق لا يثبتان تشغيل كل واجهة خلف جلسة المالك. أداة المتصفح لا تملك جلسة المالك، ولم يُستخدم تجاوز مصادقة أو حساب حي للاختبار. يمكن للمالك معاينة `/admin/plans` و`/admin/catalog` و`/admin/cards` ونموذج المركبة وتبويب التحويلات في المعاينة المستمرة؛ لا تحفظ بيانات حقيقية أثناء الفحص.
