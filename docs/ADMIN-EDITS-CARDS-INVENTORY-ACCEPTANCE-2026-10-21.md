# Pertomax EG — قبول تحديث تحرير الإدارة والبطاقات والمخزون

التاريخ: 2026-10-21
النطاق: إدارة الباقات والكتالوج، مدخل البطاقات، نموذج المركبة، وتنقل مستندات المخزون. لا يبدأ هذا التحديث حزمة جديدة.

## أثر Supabase والترحيلات

- لم يُنفّذ أي ترحيل جديد، ولم تُكتب بيانات أعمال أو أسعار أو حسابات اختبارية إلى Supabase.
- تستخدم مسارات API الحالية سببًا إداريًا افتراضيًا محايدًا عند ترك ملاحظة التعديل العادي فارغة؛ لذلك لا يلزم تغيير قيد القاعدة الحية.
- بقي `0009` مؤجلًا، ولم تُعَد أي ترحيلات أو baseline. حالة `0021` السابقة لم تتغير.

## متابعة القبول — 21 أكتوبر 2026

- أضيفت صفحة قائمة مباشرة `/admin/fuel-prices` من القائمة المركزية؛ تعيد استخدام مكون الكتالوج وواجهة API نفسها وتفتح قسم الوقود مباشرة، دون مصدر بيانات أو أسعار افتراضية جديدة.
- سُمّيت حقول مطابقة الدفتر التي يعيدها RPC صراحةً بالعربية، مع عرض العدّادات كأعداد لا كمبالغ. الحقول غير المعروفة لا تظهر كتفاصيل مبهمة؛ تعرض الشاشة تنبيهًا ولا تخلط المفاتيح التقنية مع بيانات مفهومة.
- اختبارات محددة: 3 اختبارات وحدة لأسماء حقول المطابقة وتطبيع snake_case ورفض العرض المضلل للحقل المجهول. أضيفت 12 تأكيدًا إلى اختبار API/PostgreSQL المؤقت لتعديل السعر والحقوق والإعدادات، إعادة القراءة، إعادة المحاولة، نشر إصدار مستقبلي، وثبات لقطة الاشتراك والسعر القديمة.
- اجتاز `bash lib/db/rebuild/run-local-test.sh` بعد هذه التغييرات. اجتاز `pnpm run typecheck`، وبناء الويب باستخدام `PORT=3000 BASE_PATH=/pertomax-eg-web`، وبناء API.
- لم يحدث DDL/DML على Supabase في هذه المتابعة؛ لا ترحيل أو تغيير ACL أو أسعار أو سجلات حية. `0009` ما زال مؤجلاً.
- لا تتوفر للجلسة أداة اختبار بجلد مالك؛ لم يُجر تحقق بصري محمي أو اختبار Storage حي. اختبارات التخزين المحلية محاكاة وليست خدمة Supabase Storage.

## حدود المعاينة

فحص الأنواع وبناء التطبيق لا يثبتان تشغيل كل واجهة خلف جلسة المالك. أداة المتصفح لا تملك جلسة المالك، ولم يُستخدم تجاوز مصادقة أو حساب حي للاختبار. يمكن للمالك معاينة `/admin/plans` و`/admin/catalog` و`/admin/cards` ونموذج المركبة وتبويب التحويلات في المعاينة المستمرة؛ لا تحفظ بيانات حقيقية أثناء الفحص.
