# 0014 — خطة تطبيق ورجوع إدارة الأسطول

## حد التطبيق

- المشروع الوحيد: Pertomax EG، مرجع Supabase `msvgzsfzrqlrfpstthhe`.
- الإضافة الوحيدة المقصودة: `0014_fleet_registry_and_controls.sql`.
- لا يعاد baseline أو ترحيل مطبق؛ `0009` يبقى مؤجلًا.
- البصمة التي يجب أن تطابق المصدر قبل التطبيق: `fe0ab7cbbd9f97d02ea18fabd938b36eab21a57efb462b6bff925c5de25b2357`.
- الترحيل إضافي: جداول وفهارس وقيود ودوال وسياسات، بلا تعبئة بيانات جهة أو مركبات أو حركات مالية.

## بوابة ما قبل التطبيق

1. اختبار إعادة البناء والترقية واختبارات الأسطول على PostgreSQL مؤقت؛ لا خدمة خارجية ولا بيانات حية.
2. تشغيل dry-run للمشروع المحدد والتحقق من المرجع والبصمة ووجود السجل المتوقع للترحيلات السابقة.
3. مطابقة ACL في النطاق المعتمد لكل مورد/دور/امتياز؛ يجب ألا يتغير عدد أو بصمة مجموعات ACL الافتراضية عن الأساس `65e09b76b80628c531e6e223128f0a201befefeb9eaa75685dae5dafdc337cea`.
4. التحقق من TLS `verify-full` وشهادة Supabase، ومن بقاء `petro_set_account_status(uuid,text)` وامتيازاتها.
5. مراجعة الفرق النهائي وخطة النسخة المتوافقة من API قبل تنفيذ التطبيق.

أي تعارض جديد مؤثر أو بصمة/ACL لا تطابق يوقف التطبيق؛ لا تُجرى تسوية ACL أو حذف أو إعادة إنشاء موارد لتجاوز الفرق.

## الرجوع

- كل ترحيل يطبق داخل معاملة مستقلة ويسجل المصدر وبصمته. فشل قبل `COMMIT` يعيد كامل الترحيل.
- بعد نجاح `COMMIT` لا توجد عملية `DOWN` تلقائية. إذا تعطلت النسخة: أعد تشغيل API السابقة المتوافقة أو أخفِ رابط الأسطول ومساراته، مع إبقاء مخطط 0014 وسجل الترحيل وأحداث التدقيق.
- لا تحذف بيانات أو جداول أو سياسات عكسيًا، ولا تعِد كتابة سجل الترحيل. الإصلاح بعد استخدام الوظيفة يكون بترحيل أمامي وموافقة منفصلة.
- لم تُنشأ سجلات إنتاجية للاختبار؛ البيانات الحية لا تتغير بهذا الترحيل.

## سجل التطبيق

يتعين تحديث هذا القسم فقط بعد التطبيق الفعلي:

- النتيجة: **طُبق بنجاح**.
- سجل Supabase UTC: `20261015231450`.
- البصمة المطابقة: `fe0ab7cbbd9f97d02ea18fabd938b36eab21a57efb462b6bff925c5de25b2357`.
- Postflight: نجح؛ الكائنات المطلوبة مكتملة، وسجل المصدر مطابق. لم تدخل بيانات أسطول أو دفعات.
- dry-run اللاحق: أكمل 0008 و0010 و0011 و0012 و0013 و0014 ببصماتها الصحيحة؛ `0009` غائب ومؤجل.
- ACL: 24 نطاقًا و300 سطر امتياز بقيت ببصمة `65e09b76b80628c531e6e223128f0a201befefeb9eaa75685dae5dafdc337cea`.
- دالة الحالة القديمة: بقيت ببصمة `d6a0defdb1102d00b0743723db453bad`؛ منح `authenticated=true` و`service_role=true` و`anon=false`.
- تعثر أول تطبيق بسبب أن فاحص ما بعد الترحيل كان يطلب فهرسين من `petro_private` في مخطط `public`. أُصلحت خريطة الفحص؛ المحاولتان الأوليان تراجعتا كاملتين داخل المعاملة، ثم نجح التطبيق ولم تُترك آثار جزئية.
