# AUTH-02 — طلب الانضمام الذاتي للحساب المؤكد

## النطاق والقرار

هذا التقرير يسجل استكمال مسار طلب الانضمام للحسابات المؤكدة التي لا تملك عضوية نشطة. يبقى الدخول عبر Supabase Auth باسم المستخدم وكلمة المرور؛ البريد للتأكيد والاستعادة، وليس بديلًا لاسم المستخدم في تسجيل الدخول. إنشاء الحساب أو حفظ الطلب أو تقديمه لا ينشئ عضوية ولا يعتمد جهة ولا يمنح دورًا مركزيًا. لا يتغير مسار الإنشاء الإداري بالنيابة عن مقدم الطلب المخول.

المالك وموظف العمليات المخولان يظلان المسارين الإداريين للمراجعة والقبول. لا يمكن لمقدم الطلب اختيار مستفيد آخر أو ربط طلبه بجهة قائمة يختارها، ولا يمكن لأي قبول منح دور مالك المنصة. الرفض والاستكمال والسحب وإعادة التقديم تبقى انتقالات محكومة بدوال الخادم وسياسات RLS، وليست صلاحية واجهة فقط.

## الاختبارات

- **قاعدة اختبار محلية مؤقتة:** نجح إنشاء baseline ثم `0004` مرة واحدة و`0005` و`0006` و`0007`. نجحت اختبارات مقدم مؤكد بلا عضوية، منع غير المؤكد/المعطل/صاحب العضوية من البدء، ثبات المستفيد، تكرار الطلب، مسودة/تقديم/سحب/استكمال/إعادة تقديم، قبول مرة واحدة، بقاء المسار الإداري بالنيابة، منع منح `owner`، عزل الطلب والمرفقات، وسياسات الجهات والفروع والبنك والإصدار المتزامن. اختبارات التخزين في هذه البيئة محاكاة PostgreSQL فقط، وليست رفعًا إلى خدمة Storage الحية.
- **بعد إعادة تشغيل الخدمات من هذا الفرع:** `/api/healthz` أعاد HTTP 200، والطلب إلى `/api/organization-join-requests` بلا جلسة أعاد HTTP 401، والصفحة العامة أعادت HTTP 200. سجل API بدء اتصال PostgreSQL بمشروع Supabase المعتمد.
- **الأنواع والبناء:** فحص الأنواع لكل الحزم نجح. بناء الويب وبناء API نجحا كل على حدة. أمر البناء الشامل أخفق في mockup-sandbox غير التابعة لهذا القسم لأن إعداد Vite الخاص بها يتطلب `PORT`؛ لا يعد ذلك فشل بناء Pertomax.
- **واجهة مصورة:** حُفظت صورة الصفحة العامة غير المسجلة على سطح المكتب (`central-organizations-signed-out-desktop.jpg`) والهاتف (`central-organizations-signed-out-mobile.jpg`). لا تعرض الصورتان مساحة المستخدم أو الإدارة الداخلية.
- **لم يُختبر حيًا:** دخول حقيقي، جلسة مالك أو مقدم طلب، دورة قرار فعلية، رفع/تنزيل من Supabase Storage، أو إرسال بريد. لم يُنشأ حساب حقيقي ولم يُرسل بريد اختبار. لا تعتبر استجابة HTTP العامة أو اختبارات SQL المحلية بديلًا عن ذلك.

## المعاينة والتراجع

تعمل خدمتا التطوير حاليًا من مجلد فرع `pertomax-central-orgs-20261015`؛ تغييرات أوامر التطوير محلية في ملفات إعداد المعاينة ولم تدخل في commit الفرع، وإعداد الإنتاج لم يتغير. لقطة `main` المحلي بقيت دون نقل أو دمج.

لا يوجد ترحيل عكسي منفذ أو مختبر. إذا لزم التراجع، أوقف مسارات API الجديدة أولًا، ثم راجع واستعد تعريفات دوال وسياسات `0006` المستهدفة داخل معاملة منفصلة، وأزل دالتي التحقق اللتين أضافهما `0007` فقط بعد إثبات عدم وجود اعتماد عليها. لا تحذف طلبات أو ملفات أو جداول أو حاوية، ولا تعدل سجل الترحيلات. لم يُنفذ التراجع؛ لا ينفذ إلا بموافقة مستقلة بعد مراجعة البيانات الموجودة وقتها.

## تجربة المستخدم المتبقية

من جلسة المستخدم نفسه، يمكن التأكد من أن مساحة حساب مؤكد بلا عضوية تعرض مركز طلبه، وأن إنشاء المسودة لا يمنح عضوية. لا تُدخل كلمات مرور أو رموز في المحادثة. لا تستخدم بيانات وهمية في القاعدة الحية؛ قبول طلب ينشئ/يربط جهة وعضوية حقيقية، لذلك لا تعتمد طلب اختبار أو ترفع مستندًا إلا إذا كان الطلب والملف غير الحساس صالحين فعلًا. عند توفر جلسة مالك مخولة، يكون مركز المراجعة `/admin/organization-requests`. لا ترفع أموالًا أو تستخدم بيانات حساب بنكي حقيقية للاختبار.
