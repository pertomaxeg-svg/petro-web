## التحقق المنفذ

- `pnpm -w run typecheck`: ناجح بعد تغييرات هذه الحزمة.
- `PORT=25467 BASE_PATH=/ pnpm --filter @workspace/pertomax-eg-web run build`: ناجح. أكبر ملف JavaScript عام `347.80 kB` غير مضغوط و`94.65 kB` gzip؛ جزء الأسطول `117.73 kB` و`31.73 kB` gzip.
- `pnpm --filter @workspace/api-server run build`: ناجح؛ ملف الخادم `3.0 MB` وخرائط المصدر `5.0 MB`، وهي حزمة خادم لا تُنزّل إلى المتصفح.
- طلب GET غير موثق إلى مسار عضويات مستخدم المنصة أعاد `401`؛ هذا يثبت حاجز المصادقة فقط ولا يثبت قراءة عضوية مخول.
- البناء الشامل توقف عند `mockup-sandbox` لأن أمره يتطلب `BASE_PATH` خاصًا به؛ بُنيت واجهة Pertomax وAPI المقصودتان منفصلتين، ولم تُغيّر تهيئة الأداة المنفصلة.
- لا يتضمن المشروع أمر اختبار آلي لهذه المسارات؛ المنفذ 4 فحوص قبول: فحص الأنواع، بناء الويب، بناء API، ورفض HTTP غير الموثق. لا اختبارات UI تفاعلية موثقة ولا اختبار جلسة مستخدم مخول في هذه الجولة. لن يُستخدم تجاوز مصادقة أو حساب حقيقي. فحص مراجعة آلي لم يتوفر؛ جرى فحص تغييرات المصدر يدويًا.
- لم يُطبق ترحيل أو استعلام كتابة، ولم تُنشأ بيانات اختبار حية. لا تثبت نتيجة البناء وحدها صلاحيات القراءة أو السلوك المرئي بعد تسجيل الدخول.

## ما بقي للتحقق

1. يعاين مالك مخول ملف الجهة، ملف المستخدم، أسطول الشركة، القائمة الجانبية ونموذج الإضافة على الكمبيوتر والهاتف دون حفظ بيانات اختبار.
2. يختبر مستخدم مخول قراءة عضويات المستخدم ورفع/تنزيل مرفق خاص على Supabase Storage؛ لم تُختبر الجلسة أو Storage الحية هنا.
3. مراجعة أي اختلاف مرئي أو صلاحية أثناء هذه الجلسة قبل قبول الواجهة. لا تمنع هذه البنود بناء الويب أو API، لكنها تمنع ادعاء قبول مرئي/حي كامل.
