## النطاق المنفذ

- طلب الانضمام يبدأ من صاحب حساب نشط ومؤكد البريد بلا عضوية فعالة، أو من مالك/عمليات المنصة نيابة عن اسم مستخدم مؤهل. لا يقرأ المسار أو يعرض بريد المستفيد ولا يرسل بريدًا. يفحص الخادم تأكيد الحساب والعضوية الحالية، ويمنع تكرارها. إنشاء الطلب لا ينشئ جهة أو عضوية.
- يمكن تقديم الطلب على جهة جديدة مع فرع أولي، أو ربطه بجهة معتمدة وفرع تابع لها. عند القبول تُمنح عضوية الجهة فقط؛ لا يوجد دور منصة في أدوار الطلب. لا يُسمح بربط فرع بجهة أخرى.
- مركز المراجعة يعرض طلبات الانضمام والتغييرات والحسابات البنكية والمستندات ضمن أدوارها. طلبات الانضمام نيابة عن مستخدم متاحة للمالك والعمليات فقط؛ المالية لا تستطيع بدء طلب جهة.
- حالات المسودة والإرسال والاستكمال والسحب والرفض والقبول منفصلة، مع سبب قرار وسجل تدقيق وإصدار متوقع لمنع القرار على طلب متغير.
- طلب تغيير بيانات الجهة أو الفرع يحتفظ بلقطة القيم الحالية والمقترحة؛ لا يُعتمد إذا تغير إصدار السجل منذ تقديمه. يستمر التعديل الإداري المباشر فقط بدور مخول وسبب مدقق، وتظل الحقول الحساسة خاضعة لمسار المراجعة.
- الحسابات البنكية ذات إصدارات منفصلة. الاقتراح لا يستبدل النسخة المعتمدة، والاعتماد يفحص إصدار الطلب وإصدار الحساب معًا. تفاصيل الحساب الكاملة تُعاد فقط عبر المسار المخول؛ القوائم لا تعرض الرقم الكامل.
- مستندات الجهة والفرع وطلب الانضمام محفوظة في bucket خاص `petro-private-documents`، مع سياسات تخزين تقيد كل عملية بالجهة/الفرع/الطلب. لا تُعرض ملفات المسودة لمراجع مركزي قبل إرسال الطلب. روابط التنزيل مؤقتة ومصرح بها.
- حدود الرفع: PDF وPNG وJPEG، بحد أقصى 10 MiB للملف. يتحقق API من النوع والتوقيع والحجم، ويحفظ SHA-256؛ فحص PDF أساسي فقط، **ولا توجد خدمة فحص مضاد فيروسات** ضمن الإعداد الحالي.
- لم تُضف المحافظ أو المدفوعات أو التسويات أو المركبات أو الكتالوج أو المخزون أو تطبيقات العمال أو لوحة طرف أخرى. لم تُنشأ بيانات قانونية أو بنكية أو حسابات اختبار حقيقية.

لا توجد وثيقة PRD أصلية منفصلة لدورة الانضمام أو المستندات أو البنوك أو طلبات التغيير ضمن الملفات التي تمت مراجعتها. الحقول المعتمدة هنا محصورة في المرجع الهندسي ومتطلبات المستخدم؛ لا تستنتج الوثيقة أسعارًا أو مستندات قانونية إلزامية أو قواعد مالية جديدة.

## نتائج الاختبار وحدوده

- نجحت إعادة البناء المحلية على PostgreSQL مؤقت: baseline، ثم `0004` مرة واحدة، و`0005`، و`0006`. شملت الاختبارات الموثقة في `lib/db/rebuild/organization-workflows-smoke-test.sql` إنشاء/تقديم/قرار الطلبات، الاستكمال والسحب، قبول مرة واحدة، رفض التصعيد إلى مالك المنصة، التحقق من العضوية والفرع، المستندات وسياسات التخزين المحاكاة، نسخ البنك، التزامن والتعارض، وعزل الجهة والفرع. نُظفت قاعدة الاختبار المؤقتة. لم يُتصل بـSupabase أثناء هذه الاختبارات المحلية.
- نجح فحص TypeScript للـAPI والويب، وبناء الويب. شُغّل API والويب مؤقتًا من هذا الفرع: فحص الصحة HTTP 200، الصفحة العامة HTTP 200، وقوائم الانضمام والإدارة ومحاولة الإنشاء دون جلسة HTTP 401. أوقفت خادمي الاختبار بعد التحقق.
- أفاد المستخدم أن تجربة الجهات والفروع السابقة تعمل طبيعيًا؛ هذا **اختبار أبلغ عنه المستخدم** وليس اختبارًا آليًا أجريته.
- لم تُختبر دورة الطلب أو مراجعة البنك/المستند أو التنزيل بجلسة مستخدم حقيقية. لم يُختبر رفع أو تنزيل فعلي إلى Supabase Storage بسبب عدم توفر جلسة مستخدم اختبار مصرح بها؛ إثبات وجود bucket وسياساته لا يثبت نجاح رفع ملف أو تنزيله. لم تُلتقط صورة لواجهة الإدارة بعد الدخول. لم تُنشأ حسابات أو ترسل رسائل حقيقية.

## الترحيلات والتراجع

- إعادة إنشاء بيئة فارغة: `current-schema.sql` هو baseline الموافق لـ`0001`–`0003`؛ يليه fixture محلي لـ`auth.users` ثم `0004` مرة واحدة ثم `0005` ثم `0006`. لا تُطبق هذه السلسلة على القاعدة الحية.
- القاعدة الحية لديها 0004 و0005 مطبقان دون صفوف سجل ترحيل منفصلة، كما أن 0006 مطبق الآن دون صف سجل جديد؛ لم يُعدّل تاريخ Supabase. حارس 0006 يرفض إعادة التطبيق عند وجود أي مورد مستهدف. على أي مشغّل مستقبلي فحص المخطط الحي أولًا والتوقف عند وجود الموارد، وعدم تشغيل الترحيل تلقائيًا أو إضافة سجل تاريخي دون مراجعة مستقلة.
- عند فشل قبل `COMMIT`، تتراجع المعاملة كاملة. بعد التطبيق، أوقف مسارات API الجديدة أولًا. لا تُسقط الجداول أو bucket إذا وجدت طلبات أو ملفات؛ احفظ نسخة خاصة ومشفرة من السجلات والملفات عبر مسار مصرح، ثم راجع التراجع منفصلًا. يعاد تعريف دالتي التحديث المباشر من نسخة `0005` المطابقة أعلاه، وتُزال فقط موارد 0006 وسياساتها المحددة بعد إثبات خلوها. لا تُحذف بيانات أو سجلات تدقيق، ولا تُغيّر سياسات أو صلاحيات عامة.

## قبول القسم

- **منفذ:** واجهات طلب الانضمام للمستخدم، بدء طلب مركزي باسم مستخدم، صندوق المراجعة، المستندات الخاصة ورفعها/تنزيلها عبر API، نسخ الحسابات البنكية، طلبات تغيير الجهة/الفرع، سجل المراجعة، RLS وعزل المستأجر.
- **متحقق آليًا:** SQL محلي معزول، تطابق schema قبل/بعد، TLS وهوية المشروع، صلاحيات الجداول والدوال المحددة، بقاء ACL الافتراضي والمالك، بناء/أنواع، API عام ورفض الطلبات دون جلسة.
- **معلق لتجربة المستخدم:** دخول حقيقي بحساب مالك/موظف، إرسال ومراجعة طلب واقعي، ورفع/تنزيل مستند فعلي عبر جلسة مصرح بها على الهاتف والكمبيوتر. لا يكتمل قبول الواجهة المحمية قبل هذا الاختبار.
