# Pertomax EG — قبول إدارة الأسطول المركزية

## النطاق

هذه الحزمة تخص الإدارة المركزية فقط، وتستخدم قاعدة `msvgzsfzrqlrfpstthhe`. طُبق `0014_fleet_registry_and_controls` سابقًا و`0015_fleet_subscription_options` في هذه المتابعة. لم تُدخل بيانات أسطول أو حركة مالية فعلية. لا تنشئ حسابات دخول للسائقين أو بيانات اختبار حية، ولا تبدأ دورة خدمة أو لوحة شركة أو تكامل جهاز NFC.

## نتائج الاختبارات

- اختبار PostgreSQL المعزول لـ0014: **36 assertion** تشمل حدود الأدوار وRLS، idempotency، العزل، PIN، نسخ السياسات، QR/NFC، العداد، الاستيراد وصفحات 10 قوائم.
- اختبار RPC 0015 للخيارات: **7 مجموعات تحقق** للصلاحيات والاشتراكات النشطة/المجدولة واستبعاد خطط الفروع وغير المدفوعة والبحث ووحدات المخزون المتاحة ومنع دور الدعم.
- تكامل الأسطول والمالية على PostgreSQL مؤقت حقيقي: **41 موضع تأكيد برمجي** في اختبار التكامل (وتُنفذ مواضع التحقق المشتركة كلما استدعيت) تشمل التغطية الفعلية ورفض المنتهي/العابر للشركات/المكرر/الفائض، وتقييم سياسة الوقود مقابل الزيوت، رفض الكتابة المباشرة لدور المستخدم، rollback قبل commit، إعادة نتيجة بعد commit، تعارض الحمولة/السبب، تكرار متزامن، تنافس حجزين على المتاح، تحرير واستهلاك بقيد متوازن وإعادة آمنة. الحسابات والاشتراكات والجهات كلها fixtures محلية مؤقتة؛ لا fake Supabase لهذا الاختبار.
- اختبار API المحلي المعزول: **4 assertions**؛ anonymous=401، المالك يقرأ كتالوجًا مرقّم الصفحات، شكل القائمة صحيح، ودور مالي فقط=403. تمر الطلبات عبر fake Supabase محلي ولا تتصل بالقاعدة الحية.
- مجموعة المشروع المحلية: اختبارات المستخدمين والباقات والمالية المتوازنة والتزامن السابقة، باستخدام قاعدة مؤقتة وبيانات اصطناعية.
- `pnpm --filter @workspace/pertomax-eg-web typecheck/build` و`pnpm --filter @workspace/api-server typecheck/build`: نجحت كلها. أكبر ملف متصفح 343.14 kB خامًا / 94.11 kB مضغوطًا. تحذير 2.9 MB يخص حزمة خادم Node مع خرائط مصدر 4.9 MB؛ زمن البناء نحو 2.2 ثانية وليس تحميل متصفح. لم يُرفع حد التحذير؛ لا أثر مستخدم ملحوظ يبرر التقسيم الآن.
- المخطط الحي: 0014 سجل `20261015231450` وبصمة `fe0ab7…b2357`; و0015 سجل `20261016085836` وبصمة `e3d6ed52f5a4bb6c6059bfaba085c5724f998a597a8b9332b59cb9341e7fa4b4`. نجح postflight؛ 24 نطاق ACL و300 امتياز دون تغيير، دالة الحالة القديمة ببصمتها ومنحها، و0009 ما زال مؤجلًا. 0015 أضاف دوال فقط ولم ينشئ بيانات تشغيلية.
- لا تثبت هذه الاختبارات وجود تشغيل خدمة أو كتابة NFC ميدانية أو رفع ملفات على Supabase Storage.
- دوال الحجز/الإفراج/الاستهلاك ومقيّم السياسة موجودة في المخطط، ومقيدة بـ`service_role`؛ لم يكتمل اختبارها طرفًا لطرف بتمويل وتغطية ونسخة اشتراك اصطناعية، ولا يوجد مسار خدمة يستدعيها في هذه الحزمة. لا تستخدمها لمسار تشغيل قبل ذلك الاختبار.
- إسناد التغطية اختبر فعليًا في القاعدة المحلية المعزولة فقط، لا على اشتراك حي. لم تُنشأ اشتراكات فعلية. لم يختبر التكامل حدود الوقت Africa/Cairo عند منتصف اليوم/الأسبوع/الشهر أو تغير نسخة السياسة أثناء الحجز أو نقل مركبة بعد تغطيتها.
- فحص الأنواع وبناء الويب وAPI مطلوبان في كل تسليم؛ النتيجة النهائية تسجل في سجل التسليم بعد إتمامها.

## حدود الإطلاق المعروفة

- سعر إصدار NFC مستقل ومهيأ عند 100 جنيه؛ لا توجد نقطة تحصيل NFC موثوقة مربوطة بالنواة المالية في هذه الحزمة. لذلك يبقى الطلب بانتظار التحصيل، ولا يفعّل إلا بإعفاء مالك موثق أو بعد إضافة الربط المالي المعتمد.
- الأسطول لا يفعّل خدمة أو يخصم مالًا. مسارات الخدمة المستقبلية يجب أن تتحقق من الاشتراك والسياسة والزوج، وتحجز من حساب الفرع داخل معاملة موحدة.
- لا بريد تشغيلي أو PDF أو تطبيق سائق أو تطبيق عامل أو كتابة فعلية إلى NFC.
- لم تستخدم مهارات `ui-ux-pro-max` أو `web-design-guidelines` أو `vercel-react-best-practices` لعدم توفرها في المشروع. محاولة استرجاع الوثائق الرسمية عبر الويب أعادت `402`; لذلك لا ندعي الاطلاع عليها. اتُّبعت مواصفات RTL ومبادئ النظام الحالي الصريحة.
