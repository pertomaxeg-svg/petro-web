# خطة رجوع نواة المالية 0012

النطاق المسموح: قاعدة Pertomax EG في Supabase، المرجع `msvgzsfzrqlrfpstthhe` فقط. لا تتضمن الخطة قاعدة أو خدمة أو مشروعًا آخر، ولا تغييرًا في إعدادات المالك أو ACL الافتراضية.

## قبل التطبيق

- التحقق من TLS وهوية المشروع، وبصمات ملفات 0008 و0010 و0011، وسجل الترحيلات الحقيقي، وغياب 0009.
- مقارنة موارد 0012 المحددة منفردةً؛ أي أثر جزئي أو سجل غير مطابق يوقف التطبيق بلا إصلاح تلقائي أو إعادة تشغيل.
- حفظ لقطة ACL الافتراضية الحية كاملةً (كل النطاقات والمنح) ولقطة تعريف ومنح دالتي حالة الحساب القديمتين.
- تشغيل ترقية 0012 واختبارها على PostgreSQL مؤقت، مع اختبار الرجوع عند فشل أي عبارة.
- 0012 إضافة مستقلة داخل معاملة واحدة. إذا فشل أي فحص قبل `COMMIT`، يرفضها PostgreSQL كاملةً ويُترك سجل الترحيلات كما هو.

## بعد التطبيق

- عند تعذر المعاينة أو ظهور خلل في التكامل، أوقف إظهار إجراءات المالية في واجهة الإدارة أو أعد واجهة/API المعاينة إلى النسخة السابقة؛ لا تُسقط المخطط ولا تحذف القيود أو الأرصدة أو المستندات.
- قاعدة التطبيق للمالية **إضافية**: لا رجوع حذفي بعد `COMMIT`. أصلح الخلل بترحيل أمامي صغير ومختبر بعد مراجعة الأثر، مع الحفاظ على القيود والأدلة وسجل الترحيل.
- لا يُعطّل القيد المالي بالتحرير أو الحذف. الحركة الخاطئة تُصحح بقيد عكسي مخول مربوط بالأصل وسبب محفوظ.
- بعد أي حركة مالية حقيقية، لا يُنفذ `DROP` أو إعادة تهيئة أو إعادة تطبيق للترحيل. تُجرى المطابقة أولًا، وتُحفظ كل البيانات ثم يُعالج السبب بترحيل أمامي.

## فحوص ما بعد التطبيق

- بصمة 0012 ومصدرها في سجل Supabase يطابقان الملف؛ 0009 لا يزال غير مسجل.
- عدم تغير ACL الافتراضية الحية أو تعريف/منح دالتي حالة الحساب القديمة و0008.
- تفعيل RLS على جداول الدفتر، وعدم منح أدوار العميل كتابة مباشرة، وبقاء وظائف الإدارة مقصورة على المصادقة والتحقق من الدور.
- لا يضيف 0012 أرصدة افتتاحية أو حسابات بنكية فعلية أو شحنات أو إيصالات أو قيودًا أو تخصيصات أو اشتراكات. صف الإعدادات الافتراضي يمنع تفعيل اشتراك مدفوع إلى حين اعتماد سياسة المحاسبة.
- إيقاف التطبيق إذا اختلف أي مورد أو صلاحية عن هذه الحدود؛ لا تُطابق القاعدة مع fixture ناقص ولا تُغيّر ACL غير ذات الصلة.
