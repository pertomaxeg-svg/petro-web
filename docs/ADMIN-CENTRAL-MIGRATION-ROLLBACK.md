# خطة رجوع الترحيلات الإضافية للإدارة المركزية

النطاق: Pertomax EG فقط، Supabase `msvgzsfzrqlrfpstthhe`. الخطة محفوظة قبل أي كتابة حيّة.

## الترحيلات المقصودة

- `0008_platform_user_administration.sql`: يضيف RPCs الإدارة مع إبقاء تعريف وصلاحيات `petro_set_account_status(uuid,text)`.
- `0010_plan_subscription_admin.sql`: يضيف هياكل الإصدارات والطلبات والاشتراكات، ويهيئ أعمدة النسخ القديمة كمسودات غير منشورة.
- `0011_plan_authoring_and_provider_pricing.sql`: يضيف تحرير نسخ الخطط وإعدادات الأسعار وجدولة أسعار مقدم الخدمة. ينشئ صف إعدادات وحيدًا بالقيم المعتمدة، ولا ينشئ خطة أو اشتراكًا أو طلبًا.
- `0009` مستبعد صراحةً. لا يُعاد تشغيل baseline أو ترحيل مطبق سابقًا، ولا تُضاف سجلات تاريخية مصطنعة.

## الرجوع الآمن

1. لكل ترحيل معاملة مستقلة وسجل مصدر وبصمة في `supabase_migrations.schema_migrations`. فشل الترحيل قبل `COMMIT` يعيد كامل معاملته؛ السجلات التي سبقت فشله تبقى صحيحة ولا تُعاد.
2. إذا ظهر عطل بعد نجاح ترحيل، أوقف استخدام مسارات API الجديدة أو أعد نسخة API المتوافقة السابقة، مع إبقاء المخطط الإضافي وسجل الترحيل وبيانات التدقيق. لا تنفذ `DROP` أو `DELETE` عكسيًا تلقائيًا.
3. إذا استُخدم أي RPC جديد أو أُنشئت بيانات تشغيلية لاحقًا، فالرجوع المفضل إصلاح أمامي؛ لا تُحذف اللقطات أو أحداث التدقيق أو أعمدة الاشتراكات.
4. تبقى صلاحية RPC الحالة القديمة للمستخدمين كما كانت، ويبقى 0009 مؤجلًا. لا يتغير `pg_default_acl` أو الاتصال أو TLS.
5. لا تنشأ في الاختبارات الحية حسابات أو خطط منشورة أو طلبات أو اشتراكات أو مدفوعات، ولا تُعدل بيانات جهة قائمة. اختبار السلوك على PostgreSQL مؤقت فقط.

## أثر متوقع يجب التحقق منه بعد التطبيق

- تبقى الخطط والإصدارات الأربعة الموجودة دون إعادة تسعير أو حذف؛ الإصدارات القائمة تحمل حالة `draft` إلى أن يراجعها مالك مخول وينشر نسخة معتمدة صراحةً.
- ينشأ صف إعدادات الأسعار الوحيد: 500/750/1000 جنيه لكل مركبة سنويًا، و5000 جنيه لكل فرع سنويًا لمقدم الخدمات، و100 جنيه لإصدار NFC منفصلًا. المحطات مجانية ولا تملك تعرفة تخصيص.
- لا يُنشأ سجل تحصيل أو محفظة. تفعيل الاشتراكات المدفوعة يظل معلقًا حتى بناء واعتماد ربط مالي موثوق، والتغطية التي تتطلب مركبات تظل غير مثبتة حتى اعتماد سجل الأسطول.

## نتيجة التنفيذ

طُبقت الترحيلات الثلاثة فقط على قاعدة Pertomax EG ذات المرجع `msvgzsfzrqlrfpstthhe` بعد نجاح الاختبار المعزول، وdry-run، ومقارنة ACL التفصيلية، والتحقق من TLSv1.3 وبقاء دالة الحالة القديمة. لم يُشغّل 0009 أو أي baseline أو ترحيل تاريخي.

لا تعدل هذه الترحيلات حسابات المستخدمين أو الجهات أو عضوياتها. أضاف 0010 أعمدة وصفية للنسخ القديمة ووضعها كمسودات غير منشورة دون اعتماد الحقوق التاريخية، وأنشأ 0011 صف إعدادات الأسعار المنفرد. لم تُنشأ في التطبيق الحي خطة أو تخصيص سعر أو طلب اشتراك أو اشتراك أو دفعة للاختبار. تبقى خطة الرجوع أعلاه قائمة: التراجع التشغيلي بإعادة API متوافقة مع إبقاء المخطط والسجل وبيانات التدقيق، بلا حذف عكسي تلقائي.
