## أثر قاعدة البيانات الحي

- طُبق `0012_finance_core` في معاملة واحدة، وسُجل بالنسخة `20261015190534`. بصمة المصدر SHA-256: `b0c78f1dbc4c12fe71e2c03293f3fd035ea0f3a6b538463f0a15d1f3ef37a997`.
- طابقت `0008`, `0010`, و`0011` سجلاتها ومصادرها الحقيقية وتُركت دون إعادة تطبيق. لا يوجد سجل `0009`، وما زال مؤجلًا.
- نجح postflight: 24 نطاق ACL افتراضي و300 صف منح قبل/بعد؛ البصمة `65e09b76b80628c531e6e223128f0a201befefeb9eaa75685dae5dafdc337cea` لم تتغير. لم يُعدل ACL عام أو نطاق لا يخص النواة.
- ظلت دالتا الحالة `petro_set_account_status(uuid,text)` و`petro_admin_set_account_status(uuid,text,text)` وتعريفاتهما ومنحاتهما كما كانت. القديمة: MD5 `d6a0defdb1102d00b0743723db453bad`، تنفيذ `authenticated` و`service_role` والمالك، دون `anon`. 0008: MD5 `e3b7aba0ad94b5e3c7f65a9e7875e953`، تنفيذ `authenticated` والمالك، دون `anon`.
- تحقّق التطبيق داخل المعاملة من إضافة إعداد واحد وثلاثة حسابات رقابية فقط. لم ينشئ حساب شركة/فرع أو بنكًا أو رصيدًا افتتاحيًا أو إيصالًا أو طلب شحن أو قيدًا أو تخصيصًا أو تحويلًا أو حجزًا أو تحصيل اشتراك أو حدثًا ماليًا حقيقيًا، ولم يغير مستخدمًا أو جهة أو اشتراكًا قائمًا.
- أضيفت جداول الدفتر والطلبات والمستندات والإعدادات، عرض الأرصدة المشتقة، وظائف RPC المقيدة، وسياسات RLS. لا يملك العميل صلاحية كتابة مباشرة في جداول المالية؛ العمليات تمر عبر الدوال المخولة، والمبالغ أعداد صحيحة بالقرش.

## الصلاحيات وحدود التفعيل

- المالك والمالية: قراءة وإجراءات مالية مخولة. المراجع: قراءة ومطابقة فقط. العمليات: نطاق تقديم/استكمال طلبات الشحن والاطلاع المحدود عليها، لا اعتماد قبض أو تغيير حساب مالي. الخادم يعيد `401` بلا جلسة و`403` عند غياب الدور المطلوب.
- الحسابات البنكية المخزنة ليست بيانات اعتماد تحويل: يظهر وصف البنك وآخر أربعة أرقام فقط. لا يوجد تحويل مصرفي آلي أو بريد فعلي.
- الإعداد المحاسبي الافتراضي لا يجيز تفعيل اشتراك مدفوع. يلزم اعتماد سياسة الاعتراف برسوم الاشتراك والتسوية قبل التفعيل أو تسجيل إيراد.
- لا يوجد دفتر أسطول موثوق لتغطية الشركات حسب المركبات، ولا تُنشأ مركبات وهمية. تظل تغطية الشركات وتكامل نقاط إنشاء الخدمة على مستوى المنتج اعتمادًا غير مكتمل.
- لا توجد إعدادات معتمدة للضريبة أو رسوم التركيب والاستبدال أو خصم الترقية أو دورة الاعتراف بالإيراد المؤجل؛ لم تُخترع أي منها. إيصال التحصيل منفصل عن الفاتورة القانونية.
- انتهاء الاشتراك وحجز الأرصدة لا يثبتان اكتمال دورة الخدمة. تكامل الأسطول والخدمات والتسوية خارج نطاق هذه الحزمة.

## الاختبارات والتحقق

- نجح `bash lib/db/rebuild/run-local-test.sh` على PostgreSQL مؤقت ببيانات اصطناعية: 0008 وتوافق المسار القديم، 0010/0011، دفاتر 0012 المتوازنة، الشحن والإيصالات غير المخصصة، نقل داخل الجهة، تعليق تحصيل الاشتراك، العكس، عزل الأدوار، إعادة الطلب المتكرر، وتنافس تحويلين مع بقاء الرصيد غير سالب. تحتفظ الواجهة بمفتاح التنفيذ نفسه ما دامت نافذة الإجراء مفتوحة لإعادة المحاولة بعد انقطاع الاستجابة. لم تستخدم الاختبارات قاعدة Supabase الحية أو بيانات مالية حقيقية؛ تخزين الملفات حُوكي محليًا.
- نجح فحص الأنواع وبناء الويب وAPI. تحذير البناء الوحيد حجم chunk أكبر من 500KB؛ البناء اكتمل.
- بعد إعادة تشغيل المعاينة، أفادت API باتصال PostgreSQL في مشروع Supabase المحدد. صفحة الويب ومسار `/admin/finance` أعادا 200، والمسار المالي أعاد 401 بلا جلسة كما يجب.
- لا تتوفر جلسة مالية مصرح بها في متصفح الاختبار. لم يُتجاوز تسجيل الدخول، ولا تُعد صفحة الدخول فحصًا بصريًا للوحة. يلزم المالك أو مستخدم مالي مخول فتح المعاينة لمراجعة الحالة المرئية؛ لم تُنشأ حسابات أو معاملات حية لأجل ذلك.

## التصميم والمهارات

- واجهة مالية عربية RTL ضمن الشريط الجانبي الحالي: أقسام الملخص والحسابات والبنوك والشحن والإيصالات والاشتراكات والقيود والمطابقة؛ بحث وفلاتر وصفحات، نماذج مراجعة، وحالات تحميل/فراغ/خطأ/منع صلاحية. على الهاتف يستخدم الهيكل الجانبي الحالي القابل للفتح.
- أُعيد استخدام مكونات وتوكنات Pertomax الحالية، ولم يتغير إطار العمل أو تُضف مكتبة واجهات. اعتمد التنفيذ مواصفات RTL وكثافة الجداول التي حددها المالك؛ لم أزعم الاطلاع المباشر على مراجع shadcn أو Carbon في هذه الجولة، ولم أستخدم مهارات إضافية غير مثبتة.

## خطوات معاينة المالك

1. افتح معاينة **Pertomax EG** الحالية وسجّل الدخول بحساب منصة مخول، ثم افتح `/admin/finance`.
2. راجع الملخص والأقسام؛ المراجع والمالية والعمليات سترى نطاقًا مختلفًا حسب الدور.
3. لا تنشئ إيصالًا أو شحنًا أو تحويلًا حقيقيًا للاختبار. اختبارات الكتابة موجودة في بيئة PostgreSQL المعزولة؛ أي تجربة مالية على القاعدة الحية تحتاج إجراءً تشغيليًا حقيقيًا ومخولًا.

لا نشر ولا بدء لوحة أو دورة دفع أخرى ضمن هذه الحزمة.
