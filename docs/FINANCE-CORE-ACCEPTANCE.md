## وضع الوظائف على القاعدة الحية وما ينتظر اعتمادًا

- موجودة على المخطط الحي: الحسابات الدفترية المشتقة، سجل القيود المتوازن، طلبات الشحن والإيصالات والتخصيص والتحويل والحجز والعكس والمطابقة، حدود الصلاحيات، وتفاصيل الإيصال وربط استهلاك الحجز.
- API وواجهة الإدارة تعملان من الشيفرة الحالية؛ المعاينة تحتاج جلسة منصة مخولة لفتح البيانات الحقيقية. الشحن يتطلب حساب استقبال معتمدًا ومطابقة مالية بشرية للتحويل الحقيقي.
- لا يوجد اعتماد لتفعيل التحصيل المدفوع للاشتراك: يلزم اعتماد سياسة المحاسبة/الإيراد. اشتراك الشركة يحتاج أيضًا تغطية مركبات حقيقية من دفتر أسطول موثوق. لا تُنشأ مركبات أو اشتراكات وهمية.
- لا يوجد تكامل بنك خارجي أو مرسل إشعارات أو مولد فاتورة ضريبية/PDF. إيصال التحصيل سجل داخلي، وليس فاتورة قانونية؛ لا تُنشأ محفظة مقابل رسم الاشتراك.
- لا ينفذ انتهاء الاشتراك استهلاك خدمة أو تسوية أسطول؛ ربط أهلية الخدمة بالأسطول ودورة الخدمة خارج هذه الحزمة.

## التصميم والمراجعة

- RTL عربي، شريط علوي مختصر، مسار تنقل، قائمة جانبية يمينية قابلة للطي ودرج للهاتف، تبويبات وسجلات ومؤشرات مالية منفصلة، وأزرار وإجراءات مقيدة بالدور.
- أُعيد استخدام مكونات وتوكنات Pertomax الحالية دون تغيير إطار العمل أو إضافة مكتبة واجهات. التزم التنفيذ بمبادئ الكثافة والتنقل والجداول المحددة في طلب المالك؛ لم أستخدم مهارات غير مثبتة أو أدّع الاطلاع على مصادر خارجية لم تُفتح.

## خطوات مراجعة المالك

1. افتح معاينة **Pertomax EG** وسجّل الدخول بحساب منصة مخول، ثم افتح `/admin/finance`.
2. راجع الملخص، الحسابات، الشحن، الإيصالات وتفاصيل القيد والتخصيص، تحصيل الاشتراكات، دفتر القيود، والمطابقة. جرّب طي القائمة على سطح المكتب وفتحها على الهاتف.
3. لا تنشئ إيصالًا أو شحنًا أو تحويلًا بغرض الاختبار؛ كل اختبارات الكتابة المذكورة جرت على PostgreSQL محلي مع بيانات اصطناعية.

لا نشر ولا بدء حزمة مالية جديدة ضمن هذا التسليم.
